# 09 — CRM API conventions

> **Status:** Normative, 2026-11-09. Every CRM service contract (`openapi/crm/<service>/openapi.yaml` and
> `asyncapi.yaml`) follows these rules. `openapi/crm/tools/check_specs.py` checks the ones a machine can check, and CI
> runs it. **Decided by:** [08-service-decomposition.md](08-service-decomposition.md) §10.1,
> [ADR 003](../../../docs/adrs/003-crm-funnel-conversion-boundary.md),
> [ADR 004](../../../docs/adrs/004-crm-capture-intake-and-workspaces.md).

---

## 1. Documents

| Rule | Detail |
|---|---|
| One service, two documents | `openapi/crm/<service>/openapi.yaml` (HTTP) and `asyncapi.yaml` (Pub/Sub). The services are audience, messaging, automation, sales, acquisition, insights, workspace, edge and intake. |
| OpenAPI 3.1, AsyncAPI 3.0 | The OpenAPI header comment and `x-brrtrouter-stack-size: 128KiB`; `x-brrtrouter-impl: true` on every operation. |
| Base path | `/api/v1/crm/<service>` behind the gateway. The edge is served on the tracking host (`https://t.<workspace domain>/`). |
| Self-contained | No `$ref` to another OpenAPI file: brrtrouter-gen generates one crate per document. A schema two services need (the condition tree) is copied identically; audience owns it. AsyncAPI documents do reference OpenAPI schemas and each other. |
| Generated crates | `rerp gen suite crm --service <service>` writes `microservices/crm/<service>/gen`. A contract change is not done until the crate regenerates and `cargo clippy -D warnings` passes. |

## 2. Resources and operations

- Resources are plural nouns: `/contacts`, `/campaigns/{id}`. Ids are UUIDs, generated by the service.
- A state change that is not a plain field edit is a verb: `POST /<resource>/{id}/<verb>` (`/campaigns/{id}/schedule`,
  `/tasks/{id}/complete`, `/enrolments/{id}/retry`). It returns the resource in its new state, or `202` with a job.
- `PUT` replaces, `PATCH` changes only the fields sent, `DELETE` returns `204`. Deleting something still in use is `409`
  with `reason: in_use`.
- `operationId` is snake_case and unique within the service; it becomes the handler name.
- Every operation has a `summary`, a `description` (what it does, filters, failure modes, events it publishes), and
  `x-required-role`.
- A request body never repeats a path parameter or header as a field (the generated request struct would carry it
  twice). Where an entity schema is also the body, the body is `<Entity>Input` without those fields.

## 3. Workspaces, roles and security

| Rule | Detail |
|---|---|
| `X-Workspace-Id` | Required header (UUID) on every operation except the edge's and the few marked `x-no-workspace: true` (listing and creating workspaces, managing memberships, which name the workspace in the path). |
| Isolation | Every table has `workspace_id` and row-level security on it. The gateway checks membership: a workspace the caller is not a member of is **403** (`reason: workspace_forbidden`); a record in another workspace is **404**, never 403, so ids leak nothing. |
| Authentication | `bearerAuth`: a Sesame JWT, or an API key (workspace service) acting as a service principal with its scopes. The edge is `security: []`. |
| Roles | Per workspace: `owner`, `admin`, `marketer`, `sales`, `read-only`, listed in `x-required-role` on each operation. Reads are open to every role; settings are owner/admin; sends, automations and ad audiences are marketer; deals, leads and tasks are sales (own records only unless admin). The matrix is [11-permissions.md](11-permissions.md), generated from the specs. |
| User ids | Sesame user ids, the token's `sub`: `type: string`, `maxLength: 64`, never `format: uuid`. Fields `owner_id`, `user_id`, `assignee_id`, `created_by`, `requested_by`, ... |
| Audit | Every write records actor, workspace, entity, id, action, changed fields before and after, time and request id (US_55_39). |

## 4. Lists, filters and search

- Paging is `page` (from 1) and `limit` (1 to 100, default 20). A list returns `<Item>Page`:
  `{items, total, page, limit}`, all required. A page that also carries totals is `<Item>PageWithSummary`.
- Filters are plain field names: `status`, `owner_id`, `list_id`, `pipeline_id`. No `filter_` prefix.
- Free text is `search`. Date ranges are `from` and `to` (inclusive dates); time series add `granularity`.
- Results are newest first unless the operation says otherwise.

## 5. Values

| Kind | Wire shape | Notes |
|---|---|---|
| Money | `{type: string, format: decimal, pattern: ^-?\d{1,15}(\.\d{1,4})?$}`, e.g. `"38400.00"`, beside a `currency` (ISO 4217) | As in RERP accounting: no float rounding, and the wire says exactly what the server sends. brrtrouter-gen types it `String`; handlers parse it with `rust_decimal` and write it back with `to_string()`. Goal targets and progress use the same shape whether the goal counts conversions or sums revenue. Rates, shares, probabilities and counts stay numbers. |
| Timestamps | `*_at`, `format: date-time`, UTC with `Z` | |
| Dates | `*_date` (or `from` / `to`), `format: date` | A field ending `_at` is never a date. |
| Enums | UPPER_SNAKE values | Roles are lower-case because they are identity-plane names. |
| Condition tree | `ConditionGroup` → `Condition` and `ConditionSubgroup` → `Condition` | Two levels, defined in audience and copied identically into messaging, automation and workspace. Used by segments, campaign audiences, IF/ELSE, GOAL and WAIT steps, trigger filters and export filters. brrtrouter-gen cannot generate a self-referencing schema. |
| No `allOf` | Compose by flattening the properties | brrtrouter-gen emits no type for `allOf`. |
| Organisations | `organisation_id`, `organisation_name` | Prospect companies in audience. A customer (after conversion) is RERP `crm/accounts`, linked by `customer_account_id` (ADR 003). |

## 6. Errors

Every error response is one of the shared responses (`BadRequest`, `Unauthorized`, `Forbidden`, `NotFound`,
`Conflict`, `Unprocessable`, `TooManyRequests`, `InternalError`, `ServiceUnavailable`) with an `ErrorResponse` body and
an `X-Request-Id` header:

```json
{"code": 409, "reason": "in_use", "message": "This snippet is used by 3 templates.",
 "request_id": "01JC9V4M2Q8T7R6P5N4K3J2H1G",
 "fields": [{"field": "key", "message": "already exists"}]}
```

- `reason` is stable and machine-readable (`not_found`, `workspace_forbidden`, `owner_required`, `in_use`,
  `invalid_state`, `validation_failed`, `rate_limited`, `consent_required`); clients branch on it, never on `message`.
- `422` carries `fields[]`. `429` and `503` carry `Retry-After`.
- Two operations return a domain report instead of an error body on `400`, because the report is what the screen
  shows: `POST /campaigns/{id}/schedule` (`CampaignValidation`) and `PUT /workflows/{id}/steps`
  (`StepGraphValidation`).

## 7. Retries and idempotency

- `Idempotency-Key` (header, ≤ 128 characters) is accepted on every command with an effect outside the database:
  send, schedule, test-send, sync, import, export, convert, approve, publish, recalculate, run, retry, resend, undo,
  duplicate, merge, bulk jobs. The first response is replayed for 24 hours for the same key and body.
- Every response carries `X-Request-Id`; a request may send one, otherwise the gateway assigns it.

## 8. Examples

Every JSON request body and every 2xx JSON response has an `example` that validates against its schema (JSON Schema
2020-12, formats checked). Responses the portal reads take their example from the portal's mock seeds
(PriceWhisperer `microservices/pact-mock-server/seeds/crm`), so the generated crates serve the data the screens are
built against. When a seed and the contract disagree, the contract wins and the seed is fixed.

## 9. Events

The rules for `asyncapi.yaml` are in [10-events.md](10-events.md): one topic per publishing service
(`crm.<service>.v1`), an envelope around `data`, at-least-once delivery with consumers idempotent on `event_id`, an
outbox for publishing, dead-letter topics, and `x-events` on every operation that publishes, naming the events.

## 10. Changing a contract

1. Edit `openapi.yaml` (and `asyncapi.yaml` when events change).
2. `python3 openapi/crm/tools/check_specs.py --docs` (checks, and rewrites 10-events.md and 11-permissions.md).
3. `tooling/.venv/bin/rerp openapi validate`, then `brrtrouter-gen lint --spec … --fail-on-error`.
4. `tooling/.venv/bin/rerp gen suite crm --service <service>` and `cargo clippy -p rerp_crm_<service>_gen -- -D warnings`.
5. Nothing is live yet, so there are no deprecation windows: change the portal's client and the mock seeds in the same
   change set ([12-portal-migration.md](12-portal-migration.md)). Once a service is live, a breaking change needs a new
   path version.
